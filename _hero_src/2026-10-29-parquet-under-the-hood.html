The file format underneath Delta Lake and Iceberg

1What a Parquet file is

Rows split into row groups; each column of a row group is a column chunk made of pages. A footer at the end holds the schema, offsets and min/max.

Column pruning←column chunk offsets in footer
Smaller files←dictionary, RLE, delta + snappy/zstd
Data skipping←min/max, dictionary, bloom, page index
Any engine←schema stored in the footer

Delta Lake and Iceberg store data as Parquet. They add file-level min/max in their metadata, so whole files are skipped before any footer is opened.

3When to use what

Parquet when

  • Scanning many rows, few columns
  • Write once, read many times

Delta / Iceberg when

  • Updates, deletes, concurrent writers
  • Many files: skip by file stats

Avro / a database when

  • One record at a time (Kafka, CDC)
  • Point lookups by key
Skipping depends on sort order. Sort or cluster on the main filter columns, or min/max ranges cover everything.

4Data skipping, coarse to fine: each answers "definitely not" or "maybe"

aPartition pruning

Directory names. Table layout, not Parquet. Plan: PartitionFilters.

bRow group min/max

Footer stats. Skips row groups only if data is sorted or clustered.

cDictionary filter

For = and IN on low-cardinality columns.

dBloom filter

For = on high-cardinality ids, where min/max can't help.

ePage index

Skips pages inside a surviving row group.

Then: survivors are decompressed and decoded, and Spark re-checks the filter on every row (the Filter node above the scan).

5Reading the Spark plan

// Scala
spark.read.parquet("events")
  .where($"event_date" === "2026-10-01" && $"country" === "IE"
         && upper($"device") === "IOS")
  .select("user_id", "country", "amount")
  .explain("formatted")

PartitionFilters: [event_date = 2026-10-01]  → dirs
PushedFilters: [IsNotNull(country), IsNotNull(device),
                EqualTo(country,IE)]        → blocks
ReadSchema: user_id, country, device, amount
Filter: country = IE AND upper(device) = IOS  → rows

6Look inside with parquet-cli

parquet meta frow groups, encodings, min/max
parquet pages fevery page; spot dictionary fallback
parquet dictionary -c country fwhat the dict filter checks
parquet column-index -c date fpage-level min/max + offsets
parquet bloom-filter -c user_id -v u-42 fbloom answer per row group
parquet footer fthe whole footer as JSON
parquet-cli replaces the deprecated Java parquet-tools.
Learn by diffing: write sorted vs unsorted, compare meta.

7Key takeaways

  • Footer first: schema, offsets, min/max
  • Select few columns: pruning is free
  • Sort on filter columns, or min/max skips nothing
  • Bloom filters for equality on ids
  • Keep filter columns bare: no functions or casts

Common mistakes

  • Reading PushedFilters as proof of skipping
  • upper(col), year(date) in filters
  • Thousands of tiny files, tiny row groups
  • Spark's default INT96 timestamps: no min/max
Rule of thumb: read few columns, filter on bare columns, and sort the data the way you filter it.
Verify: filters in PushedFilters; rows decoded drop; parquet meta ranges narrow.
